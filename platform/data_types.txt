# Field layouts for game data the decomp stores as big-endian byte arrays.
#
# Many data units define objects as `u8 lbl_xxx[N] = { 0x02, 0x80, ... }`,
# the bytes in the GameCube's big-endian order. On the little-endian 3DS a
# 16- or 32-bit field read from such an array comes out byte-swapped.
# tools/unify_prototypes.py rewrites the initializer of every symbol listed
# here, reversing the bytes of each multi-byte field.
#
#   layout NAME = FIELDS      define a layout; FIELDS are b (1 byte),
#                             h (2), w (4), d (8), each with an optional
#                             repeat count: h7 is seven halfwords
#   SYMBOL NAME               symbol has that layout; if it is a whole
#                             number of layouts long, it is an array of them
#
# Entries need evidence: an SDK type, or the access widths the original
# code uses on the object.

# tvmode (+0), 7 halfwords fbWidth .. viHeight (+4), 2 bytes padding,
# xFBmode (+20, word-aligned), field_rendering and aa (+24),
# sample_pattern[12][2] (+26), vfilter[7] (+50), padding to 0x3C.
# Checked against the data: lbl_803130F0 has 00 00 at +18 and
# xFBmode = 00 00 00 01 at +20. (An earlier version of this line put
# xFBmode at +18; tools/access_widths.py exposed it.)
layout GXRenderModeObj = w h7 b2 w b2 b24 b7 b3
